# 断语质量基线（tests/drift）

排盘层有 14.8 万条断言守着「算得对」，但「断得怎么样」此前一条都没有。
本目录把那个不可言的「准确率」拆成四个**可判定**指标，让「提高」这个词第一次有定义。

```bash
npm run test:drift          # 出基线报告 + 指标自检（默认不阻断）
npm run test:drift:strict   # 未达门槛则 exit 1（基线改善后再启用）
node tests/drift/run.mjs --json           # 机器可读
node tests/drift/run.mjs --only=<case-id> # 只跑一个 case
```

## 四个指标

| 指标 | 定义 | 门槛 | 为什么可判定 |
|---|---|---|---|
| 引擎一致率 | 断语结论方向 == `analyze().trend` | ≥ 80% | 引擎有确定性 trend，断语与自家规则打架是纯客观错误，不涉流派 |
| 同盘冲突率 | `1 - 最大方向占比`（同 case 内多条断语） | ≤ 20% | 同一张盘同一问事，方向本就该收敛 |
| 要素错误率 | `auditFactClaims` + `auditCoverage` 判出冲突的断语占比 | ≤ 5% | 盘面写反、静爻论冲、取用两说都有确定对错 |
| 边界遵守率 | 无独断词（必然/绝对/保证）且未宣称准确率的断语占比 | ≥ 90% | 只碰「不可证伪的断言」，不评价推断本身 |

**四个都是下限指标。全绿只等于「没犯可判定的错」，不等于断得准。**
吉凶对错在六爻体系内无金标准——同一张盘，古书本身就有两说（见主 README §已知口径分歧），
程序无权判它。所以本目录**从不**回答「准不准」，只回答「有没有犯可判定的错」。

## 为什么默认不阻断

`corpus/2026-10-21-kun-weijing.json` 是真实采集：同一张盘、同一 provider 两次独立调用，
一次判「平」、一次判「凶」。当前基线是

```
引擎一致率 50%   门槛 ≥ 80%   FAIL
同盘冲突率 50%   门槛 ≤ 20%   FAIL
要素错误率 50%   门槛 ≤ 5%    FAIL
边界遵守率 100%  门槛 ≥ 90%   PASS
```

基线本身未达标。此时让 CI 变红只会逼人关掉它，所以 `test:drift` 恒 exit 0，
只把数字长期摆在眼前。等指标真的改善，再改 `test:drift:strict` 进门禁。

**改门槛须单独提交并说明理由**——否则「提高」会退化成「调标准」。

## 加入新语料

新增 `/tests/drift/corpus/<日期>-<卦名>.json`，**不改代码**：

```json
{
  "version": 1,
  "cases": [{
    "id": "2026-10-21-kun-weijing",
    "question": "所测何事",
    "chart": {
      "vals": [0, 6, 6, 0, 6, 0],
      "at": { "y": 2026, "m": 10, "d": 21, "h": 12, "min": 1 }
    },
    "target": "父母",
    "source": "哪个 provider、调用几次",
    "replies": [ { "provider": "deepseek", "label": "第一版", "text": "…全文…" } ]
  }]
}
```

- `vals` 编码：`1` 少阳 / `0` 少阴 / `9` 老阳动 / `6` 老阴动。
- `at` 用**年月日时分字段**而非 ISO 字符串——避免时区差异让同一份语料在不同机器上跑出不同盘。
- `text` 必须是模型原始输出的断语全文。**删改语料等于改基线**，须单独提交并说明理由。
- 结论方向解析优先认显式 `结论：吉/平/凶`；无此字段才按句计分，并列时判「未表态」不硬猜。

## 两类 abstain 是刻意的

- 断语没表态 → 不入分母（不然含糊其辞反而拉高一致率）。
- 吉凶句数并列 → 返回 `null` 而非取多数（评测器不该比断语本身更武断）。

## 第三类：显式分歧（`declared`）

提示词的【结论对齐】契约允许模型不同意引擎判定，但要求**声明**：

```
结论：凶（与引擎分歧：引擎判平，此处判凶）
```

评估器把这类从「引擎一致率」分母里剔除，单列为 `declared` 计数。
理由：契约若一边说「允许分歧」一边照扣分，模型唯一理性选择就是沉默照抄引擎——
那等于把断卦退化成规则回显。但**未声明**的相反结论照扣，不豁免。

看报告时请把 `declared` 和目标分开看：`declared` 突然升高不是进步，是模型开始赖账；
它应当是低频、附带古法理由的例外。

## A/B 对照怎么读

`corpus/` 里现在有两组同盘语料：

| 文件 | 何时采集 | 结果 |
|---|---|---|
| `2026-10-21-kun-weijing.json` | 引擎判定注入**之前** | 平/凶 各一，冲突度 50%，一致率 50%，1 条含 2 处硬伤 |
| `2026-10-21-kun-weijing-v2.json` | 注入**之后** | 两条都是「平」，冲突度 0%，一致率 100%，0 硬伤 |

读法三条：

1. **每臂 n=2，不能说「已收敛」。** 只能说「注入后没再看到反向证据」。要下结论需把样本提到 N≥5 并补第二个卦、第二个 provider。
2. **旧语料不删。** 删掉 v1 就等于「只统计成功的实验」，聚合指标会假性好转。
3. **看聚合不要看单 case。** 聚合里 v1 的两条仍在，所以报告仍是 75% / 25% / 25% —— 门槛未达标。这是正确状态，不是回归。

> 采集注意：采集脚本必须先「按卦名排 + 补录时刻」精确复现原盘，且断言 `panText` 同时含本卦与变卦名，否则随机摇卦会静默换盘、A/B 直接失效（本轮踩过）。

## ⚠ 上游缓存会让「同盘冲突率」失效

2026-10-21 查网关 API 坐实：`liuyao-gw` 的 `cache_ttl` 虽为 0，但 40 条日志里 **27 条 `cached: true`**（HIT 时 tokens 0、耗时 73–319 ms）。**`cache_ttl: 0` 不等于不缓存。**

缓存键 = `provider + endpoint + model + 鉴权头 + 完整请求体` 的 SHA-256（官方文档明载），所以：

- 同一请求体重发必命中 → 「连发 N 次」拿到的是**同一份答案**，冲突率恒为 0，是伪像不是稳定。
- panText 尾部加一个换行就换 key、返回全新响应（实测）。

采集独立样本的两条路：

1. **传 `skipCache: true`**（`/api/interpret` 请求体字段，透传 `cf-aig-skip-cache: true`）。默认关闭，只为评测/重试准备。
2. 每次请求微扰无关空白（脏但有效）。

在此之前，报告里的「同盘冲突率」应视为**下限未知**，不要拿它宣传稳定性。

另注：缓存会把**截断/失败响应一起固化**。gemini-3.6-flash 曾稳定返回 470 字符残句（`finishReason=STOP`、137 tokens），被缓存后每次都是它——服务端现已加 `MODEL_*` / `INCOMPLETE_STRUCTURE` 两类告警。
