# tests/verify —— 外部验证集三方对账

用途：当有人拿来一份**外部给的排盘验证集**（不是从古籍原文取的卦例），
判断分歧到底是「我们错了」还是「用例错了」。

核心原则：**不拿引擎给自己作证**。每一条分歧都要由独立裁判库复核。

## 两层门禁（分工不同，都进 `test:all`）

| 命令 | 文件 | 依赖 | 回答的问题 |
| --- | --- | --- | --- |
| `npm run test:verify` | `run.mjs` | 三家裁判库 | 「这份外部用例集，分歧该怪谁？」（判责） |
| `npm run test:paipan` | `regress.mjs` | **零依赖** | 「引擎是否偏离了已裁决的基线？」（断言） |

金标准只在**重新裁决**（`run.mjs --fix`）时才会变动。日常回归不需要裁判库在场——
`regress.mjs` 只加载 `core.js`，CI 里 `npm ci` 失败、离线、或想快速自检时都跑得动。

## 文件

| 文件 | 说明 |
| --- | --- |
| `external-suite-v1.json` | 外部提供的验证集，**逐字节原样落盘，未改动** |
| `external-suite-v1.1-adjudicated.json` | 由 `--fix` 生成的「裁决后」用例集：每个字段都要求本引擎与≥1 家裁判库一致才写入 |
| `run.mjs` | 对账器（判责） |
| `regress.mjs` | 金标准回归（断言，零依赖） |

## 裁判库（devDependencies，不进生产）

| 库 | 角色 |
| --- | --- |
| `@taoracle/najia` | 排盘主裁判。TypeScript 移植自 Python `najia`，与上游在 4⁶=4096 组合上零差异；另带 `attack`(六冲) / `unite`(六合) / `soul`(游魂归魂) 三个独立实现 |
| `iching-shifa` | 交叉裁判，独立实现的六爻筮法库 |
| `lunar-javascript` | 第四方历法裁判，只用于四柱维度 |

## 判责规则

对每个字段取三方值（用例期望 / 本引擎 / 裁判库）：

| 情形 | 判定 |
| --- | --- |
| 用例 == 引擎 | `ok` |
| 用例 ≠ 引擎，且 ≥2 家裁判库站引擎侧 | **用例错**（`case-wrong`） |
| 用例 ≠ 引擎，且 ≥2 家裁判库站用例侧 | **★引擎错**（`engine-wrong`）→ 退出码 1 |
| 其余 | `存疑`（`unknown`） |

另有一条与引擎**完全无关**的检测：只用裁判库由 `coins` 推卦画/卦名，
去比用例自称的 `original_gua` / `changed_gua` / `is_liu_he` / `category`。
这条能抓「用例自相矛盾」——不需要引擎表态就能定案。

## 用法

```bash
npm run test:verify                    # 对账裁决后用例集（回归门禁）
npm run test:paipan                    # 金标准逐字段断言（零依赖，无需裁判库）
node tests/verify/run.mjs              # 对账原始外部用例集
node tests/verify/run.mjs --suite <f>  # 指定用例集
node tests/verify/run.mjs --json <f>   # 另出机读结果
node tests/verify/run.mjs --fix <f>    # 生成裁决后用例集（拒绝写入无裁判背书的字段）
```

`--fix` 的护栏：某字段若引擎值与所有裁判库都不一致，**不写入**修正值，
而是列进「无背书字段」清单。避免把引擎的错误当成标准答案固化下来。

`regress.mjs` 的 `description_check` 是生成裁决集时留下的机读档案，
与当前引擎不符时**只提示不判失败**（档案漂移），以免为了改档案而必须先装裁判库。

## 已发现的问题（v1.0 用例集）

详见仓库根目录《六爻第十三轮-外部验证集三方对账.md》。摘要：

- **4/4 条用例的日柱都不对**，且偏移量各不相同（-11 / +10 / -15 / -15 天），
  属虚构而非系统性口径差；旬空（4 条）与六神（24 处）随日柱连带出错。
  年柱、月柱 4/4 正确。
- **TC_003 用例自相矛盾**：`coins` 推得变卦「坤为地」，用例自称「雷天大壮」。
- **TC_004 用例自相矛盾**：`coins` 推得本卦「地山谦」，用例自称「水地比」；
  且即便按它自称的水地比，该卦也不在八六合卦之列，「六合卦」标注同样是错的。
- 引擎侧被裁判库判负：**0 项**。

## 附：八宫卦型全枚举（64 卦）

下列四表最初由 najia 的 64 卦表独立枚举得出（与本引擎无关），
现**已落地为引擎能力**（`core/paipan.js` 的 `chongGua` / `heGua` / `soulGua`，
并暴露为 `paipan().isLiuChong / isLiuHe / soul`），
由 `test-gua-types.js` 用**京房八宫卦次**（64 卦整表）独立锁定，并附 10 项变异自检。

- **六冲卦 10**：乾为天、坤为地、震为雷、巽为风、坎为水、离为火、艮为山、兑为泽、天雷无妄、雷天大壮
- **六合卦 8**：地天泰、天地否、地雷复、雷地豫、水泽节、泽水困、山火贲、火山旅
- **游魂卦 8**：火地晋、地火明夷、风泽中孚、泽风大过、山雷颐、天水讼、水天需、雷山小过
- **归魂卦 8**：火天大有、地水师、风山渐、泽雷随、山风蛊、天火同人、水地比、雷泽归妹

互斥性：六冲 ∩ 六合 ∩ 游魂 ∩ 归魂 两两为空；既非六冲亦非六合者 46 卦。

### 一处实测得到的冗余性质

本纳甲体系下内卦与外卦的纳支对应是刚性的：初-四一旦相冲/相合，二-五、三-六自动成立。
故「三对皆冲」与「仅查初四」在 64 卦空间上给出**同一集合**（实测四档取值完全一致）。

这不是巧合而是纳支表结构的推论。引擎按定义写全三对（可读、贴合传统表述），
冗余性由 `test-gua-types.js` 第九节显式锁定——将来若改动纳支表而破坏此性质，会收到提示。
同时这也解释了为何该文件收录的变异里**不包含**「只查一对/两对」：改不动输出即非有效变异，收进来只会产生假警报。
