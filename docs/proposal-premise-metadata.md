# 前提元数据 · 缺项分级 · 应期同域（M21 方案与实施）

> 触发案例：问「今年能不能考上市重点」，模型把「今年」当本招生年度、把对象阶段默认成
> 应届、给出「甲子日」这种日级应期。用户要的不是把升学写进通用规则，而是让**任何领域**
> 都先核一遍前提，并在输出前校验应期粒度与事项跨度是否同域。
>
> 结论一句话：从「案例驱动」改为 **通用前提元数据 + 风险分级澄清 + 领域适配包 +
> 应期同域一致性校验**。本文记录修订后的条目、实现落点与验收口径。

## 一、抽象层级（为什么不能把升学写成通用规则）

四层结构，越往下越具体，只有最上面两层进系统提示：

| 层 | 内容 | 落点 | 是否进通用提示词 |
| --- | --- | --- | --- |
| L1 原则 | 五类通用前提（时间范围／对象阶段／目标标准／进程状态／规则环境）+ 两级风险 | `SYSTEM_PROMPT` 的【前提元数据】【缺项分级】 | 是（与领域无关） |
| L2 校验 | 应期粒度不得细于事项跨度；被证伪须按模板撤回 | `SYSTEM_PROMPT` 的【应期同域】【应期撤回】 | 是 |
| L3 领域包 | 某领域里「时间锚点」是什么、哪些槽位算关键、典型刻度是月还是年 | `public/core/domain-methods.js` 的 `premise` 字段（按用神分）+ `premise.js` 的 `KEYWORD_PACKS`（按事由关键词分） | 只进**预检块**，按本次事由实例化 |
| L4 实例 | 「今年」在升学里指招生年度、在回款里指账期 | 预检块的「口径歧义」行 | 逐次生成 |

判断标准：一条规则若离开某领域就不成立（如「考上要看分数线」），只能待在 L3/L4；
能在任何领域复述的（如「缺时间范围就别给单一应期」）才升到 L1。

## 二、修订后的条目

### R1a 通用前提元数据与风险分级（已实现）

- 五类槽位与判据见 `public/core/premise.js` 的 `SLOTS` / `SLOT_RE`。
- 风险分级不是「缺项就拦」，而是双条件：
  - **高风险** = 缺项会翻转结论方向或应期量级，**且**本类事项确实需要它：
    - 进程状态：本类把它列为关键时（官讼看审限、占病看近久病）；
    - 目标标准：问法本身是「达成某结果」（`GOAL_RE` 命中「考上／签约／入职…」）；
    - 对象阶段：本类把它列为关键时。
  - **中风险**：只见目标不见门槛（`partial`）——可给结论，但须写明所设门槛口径。
  - **低风险**：只影响细节，标注「前提未定」照常输出。
- **时间范围缺失不升为高风险**：由本类典型刻度兜底，且必须在正文写明「这是假设」。
  理由：若把「没说清是这几天还是今年」一律拦成追问，绝大多数正常问卦都会被挡住。
- 反向对照（已入测试）：`这周会不会来电` 缺「目标标准」**不**升为高风险；
  `下个月能签合同吗` 缺「目标标准」**要**升为高风险。

### R1b 领域适配包是配置，不是提示词里的硬编码（已实现）

- 两个来源，同一个形状 `{ anchors, decisive, typicalSpan, spanNote }`：
  1. `core/domain-methods.js` 七个用神值各带 `premise`（妻财／官鬼／父母／子孙／兄弟／shi／__custom__）；
  2. `core/premise.js` 的 `KEYWORD_PACKS`：升学／求职／诉讼／健康／交易／感情六包，
     只在「自定义所测」时按事由关键词挑包（升学是其中之一，不是唯一）。
- 领域包只影响**预检块与应期刻度**，不碰用神、不碰 trend、不碰盘面。
- 测试锁住：七个用神值都有 `premise` 且字段齐全、`typicalSpan` 合法；关键词包 ≥5 个。

### R3 应期同域一致性校验（已实现）

`premise.checkYingqi(应期行, 跨度)` 的判定表：

| 事项刻度 | 应期写法 | 结果 |
| --- | --- | --- |
| 年／季 | 干支日、第 N–M 日、N 日内（无任何粗刻度） | **violation** `YINGQI_TOO_FINE`（须撤回） |
| 年／季 | 干支日 **＋** 月份／季度／流程节点 | warn `YINGQI_DAY_AS_AUX`（日级只作辅，主刻度已给） |
| 年／季 | 月份、季度、流程节点 | 通过 |
| 月 | 裸干支日（无公历区间） | warn：日级只在旬内之事成立 |
| 月 | 干支日 + 公历区间 | 通过（引擎应期窗口本身常给「癸未日前后（11月5日—11月7日）」） |
| 旬 | 干支日 | 通过 |
| 日／旬 | 只有年份 | warn `YINGQI_TOO_COARSE` |
| 跨度未明示 | 任意 | 不判（无判据） |

- **与引擎窗口和解**：引擎的应期窗口本身就是「癸未日前后（11月5日—11月7日）」这种日级写法，
  由出空／值日／逢冲换算而来。跨年之事引用它作辅助节点并不矛盾，故月／季与日级同时出现时
  只判 warn（`YINGQI_DAY_AS_AUX`），不判 violation；预检块另写一行「窗口是节点、不是应期」，
  让模型知道该怎么用。**不和解的后果**：模型要么违背引擎窗口，要么把节点当应期，
  前端再判它冲突——三条规则互相打架，最后谁都不信。
- 前端在断卦完成、渲染结论卡之前跑这一步，**violation** 时给红色告警＋**撤回模板**原文；
  warn 只用灰字提示，不给撤回句——「原应期作废」是很重的话，滥用会让它失去分量。
- 系统提示侧只留原则（L2），具体计算在前端确定性层完成——与 fact-audit / coverage-audit 同一分工。

### R4 输出暴露「前提完整性」（已实现）

- `SYSTEM_PROMPT` 的结构化结论由四行扩为**五行**：
  `结论／应期／验证标志／用神／前提完整性`。
- `parseConclusion` 解析该行并在结论卡上显示：
  - 模型自报「完整」→ 灰字；
  - 自报「缺失/前提未定」→ 黄字（不是错误，是「这份断语在哪种前提下成立」）；
  - **漏报而引擎判定有高风险缺项** → 显式提示「前提 未申报（引擎预检：X 属高风险缺项）」。

### R5 应期撤回与同盘追问（已实现）

- 撤回模板：`原应期 X 作废：（与哪条前提/盘面要素）冲突；在新前提下应期应落在（N 刻度），需另起一卦重断。`
  出现在两处：系统提示的【应期撤回】（约束模型）与前端冲突卡（给用户看的成品句）。
- 同盘追问：`premise.followUpHint(上一轮结论, 本轮问题)` 比较前后跨度，
  变了就生成「原应期 + 跨度变化」提示，随排盘文本发出——旧版追问全程不提，
  模型会静默把日级应期改写成新的日级日期，用户以为断的还是同一件事。

### R6 通用回归断言（已实现）

`test-premise.js`（110 断言）+ `test-functions.mjs`（新增 13 断言）：

- 跨度判定 16 条，含四条反向对照（`半个月`≠月、`半年`≠年、`这学期`≠月、`这周`≠日）；
- 缺项分级跨升学／短讯／诉讼／求职／健康／交易／感情七种问法，防单领域硬编码；
- 应期同域 12 条（含「月 + 干支日 + 公历区间」放行、「旬 + 年份」过粗）；
- 撤回模板与追问提示 9 条；
- 提示词契约：四段标记两份文件都在、结构化结论为五行、通用段必须出现「领域适配包」
  与「示例只示范写法」（防止有人把升学槽位表搬回通用段）；
- 服务端兜底：不带预检块的排盘文本被补一段、带了不重复追加。

### R7 结论带依据（沿用）

原【结论须带依据】不动；撤回句与冲突卡同样要求写明冲突对象，不新增条款。

## 三、提示词差异说明（改了什么、为什么）

| 段 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| 【前提未定】 | 只覆盖「近病久病」这类**具体前提** | 保留原文，作为低风险情形的落点 | 老条款仍有效，不必推翻 |
| 【前提元数据】 | 无 | 新增：五类通用槽位 + 「示例只示范写法，不是通用槽位表」 | 给模型一张“该核对什么”的清单，同时明确它不隶属任何领域 |
| 【缺项分级】 | 无 | 新增：两级风险 + 不得替用户假定未说出的前提 | 旧版真正的问题是**默认值不写在输出里**，用户看不见 |
| 【应期同域】 | 【应期按域】只管「落在引擎窗口内」 | 保留【应期按域】，新增粒度约束 | 窗口只管时间位置，不管粒度：跨年之事仍可被写成「甲子日」 |
| 【应期撤回】 | 无 | 新增模板句 | 用户补一句前提后，旧版是**静默改写**，读起来像同一份断语 |
| 【结构化结论】 | 四行 | 五行，`应期` 行改为「同域粒度」，新增 `前提完整性` | 让前提状态成为可解析、可展示的结构化字段，而不是散在正文里 |

排盘文本侧新增一段（不进系统提示，逐次生成）：

```
【前提预检（规则链 · 非推断）】
- 时间范围：题面「今年」→ 以「年」为刻度
- 口径歧义：题面用「今年」，而本类事项的时间锚点是招生年度／考期…须写明按哪个算
- 已明示：时间范围「今年」；目标标准「考上」（只见目标，未见具体门槛）
- 低风险缺项：对象阶段、进程状态、规则环境——只影响细节，标注「前提未定」照常输出结论。
- 应期同域：本类事项刻度为「年」，应期只能给月／季／年或流程节点，不得写具体干支日。
- 如需补充（用户问一句即可，不必全填）：要达成的具体目标与门槛是什么。
```

服务端兜底：直接用 API 打 `/api/interpret` 的调用方没有这一段，函数侧检测到
「无【前提预检」就补一句「无预检结果，须自行核对五类槽位并在正文声明假设，
时间跨度不明确时不得给具体干支日」——防止绕过前端又退回默认时间跨度。

## 四、验收标准（已满足）

| 编号 | 标准 | 验证方式 |
| --- | --- | --- |
| E1 | 跨年之事给日级应期 → 被判定为冲突并给出撤回句 | `checkYingqi` + 前端冲突卡；`test-premise.js` §3 |
| E2 | 月份刻度给出「干支日 + 公历区间」→ 放行 | 同上（引擎应期窗口的常规写法不被误伤） |
| E3 | 缺关键前提时不单断，缺非关键前提时照常结论 | §2 短讯/诉讼/目标类三组正反用例 |
| E4 | 前提完整性出现在结构化结论里并可解析显示 | `parseConclusion` + 卡片渲染；`test-functions.mjs` 契约组 |
| E5 | 用户补充信息改变跨度 → 追问提示触发撤回 | `followUpHint` 4 条断言 |
| E6 | 通用段不含领域专属槽位表 | 断言含「领域适配包」「示例只示范写法」 |
| E7 | 绕过前端的请求也不退回默认跨度 | `test-functions.mjs` 兜底 5 条断言 |

## 五、开放问题（未做，别当成 bug）

- **预检只在自然语言层面**：题面用词不覆盖时（如「这阵子」）会落进 unknown，此时按本类
  典型刻度兜底——兜底正确率取决于领域包，样本够了再调。
- **应期同域只判粒度，不判合理性**：模型给「三年后」对一件旬内之事会被判过粗，
  但给「下季度」对一件月内之事不会报——中档偏差留给人工回填。
- **领域包与用神下拉可能不一致**：选「父母」却问官司时，包取的是父母包（用神优先），
  关键词包只在 `__custom__` 生效。若要合并，需要一张领域×用神的交叉表，等样本。

## 附：古法出处（规则可追溯）

本层的每一条判定都不是新创，而是把《增删卜易》《卜筮正宗》已写明的操作原则
落成机器不会绕过的检查节点。**引文按通行本大意转录，版本字句待校**——
若要对外引用，须先核所据版本（本项目尚未做版本校勘，标注于此以免误引）。

| 古法原则 | 出处（大意） | 工程落点 |
| --- | --- | --- |
| 远近当分 | 「远事定之以年月，近事应之于日时。」《卜筮正宗·各门类应期总注章》原样收录此总纲 | `checkYingqi()`：应期粒度不得细于事项跨度 |
| 分行人之远近 | 「问行人之归期，有远有近。远则应月，近则应日。」 | 同上（`spanOf` 五档刻度即此分层） |
| 须指其所疑之事而占 | 「若以一卦而断全家之事者，予则不能，须指其所疑之事而占之。」 | `judge()`：高风险缺项 → 首轮不得单断 |
| 卦有恍惚者再占 | 「卦之恍惚者，再占一卦，不可妄断。」 | `followUpHint()` ＋ 撤回模板「需另起一卦重断」 |
| 一事一卦 | 「我占必以真告，切莫昧己。」 | 追问沿用原盘；事项实质变化则另占 |

**工程化不是背离古法，是把隐性知识变成检查节点**：古法的「问清楚」依赖卜者临场判断，
AI 没有这种判断力，故须由规则链在出结论前拦一道。这与古法同源，不是另创一套。

### 一处真实分歧（待定，未做）

需求文档原文写的是「**高风险前提未确认时，首轮不进入断卦**」，但当前实现是
「**首轮不得给单一吉凶与单一应期，先说明缺什么，再按可能情形给条件分支**」——
模型照样断，只是断成多支，并非拒断。

| 方案 | 行为 | 代价 |
| --- | --- | --- |
| A（现状） | 条件分支，正文照常输出 | 用户仍可能只读第一支当结论 |
| B | 出「澄清卡」不出吉凶，用户补充后再断 | 多一轮交互；题面无解时无法收尾 |
| C | 仅当「时间范围＋对象阶段」同时缺（远近无从定）时阻断，其余走 A | 折中，但判定边界需再定 |

未擅自改成 B：会改变产品主流程与用户预期（现在点一次就有断语），须你拍板。

### 一处规则打架（已修）

`【应期按域】`要求「应期行须落在引擎窗口区间内」，而引擎窗口是出空／值日换算出的**日级**区间；
`【应期同域】`又禁止跨月跨年之事写干支日。跨年之事两条同时成立时，模型只能二选一，
它选了服从前者（措辞更硬：不得脱离区间）——**原始案例里的「乙酉日—辛卯日」很可能由此而来，
不是模型随口给的**。

修法：在【应期按域】末尾显式定优先级——与【应期同域】冲突时以后者为准，
窗口降为「节点辅证」，主刻度须落到月／季／年或流程节点。
