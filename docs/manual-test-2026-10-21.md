## ⚠ 先知道一件事：断卦会变慢

首轮断卦**不再走网关缓存**。以前同一盘重复断卦是秒回（命中缓存 73–319ms），
现在每次都是真生成 —— 实测 deepseek **63–98 秒**。

这是为修「残篇被缓存固化」付的代价。若觉得太慢：
把环境变量 `LLM_CACHE_FIRST=1` 设上即可恢复旧行为（但残篇会重新被固化）。

## 1. 首轮断卦不再命中缓存

- 起一卦 → 选事类 → 断卦，记下回答。
- **不改任何东西**，再点一次断卦。

- [ ] 两次回答**内容不同**（以前会一字不差）
- [ ] 两次耗时都在 1 分钟左右，不是秒回

> 若第二次仍秒回且内容一致 → 缓存没绕过，看部署版本是否为 `4566070c`。

## 2. 引擎判定是否被采纳

断语拉到最末，应看到结构化四行：

```
结论：吉 / 平 / 凶
应期：…
验证标志：…
用神：…
```

- [ ] 「结论」行与页面上「**粗判（趋吉 / 趋凶 / 持平 / 待审）**」方向一致
  （平↔持平、吉↔趋吉、凶↔趋凶）
- [ ] 若不一致，断语里应有「（与引擎分歧：引擎判X，此处判Y）」的括注

## 3. 断语未完篇的提示

- [ ] 若断语在中途断掉（没到「结论：」行），文末应出现：
      `⚠ 本卦断语未完篇（…）。建议重试或换模型。`
- [ ] 换 gemini 试一次更容易触发（它偶发提前收尾）

## 4. 断后审查不再乱报（今天修的主要是这块）

之前会对下面这类**正确写法**误报红字，现在应当放行：

- [ ] 断语引用古法条文（如「《卜筮正宗》谓"旺不为空，动不为空"……」）→ 不报
- [ ] 列表小标题「- 月破：盘面未列爻逢月破」→ 不报
- [ ] 但**真的写错**仍要报，例如盘面无月破却断言「用神月破，凶」→ 应报

> 这条是今天最容易回归的一处：修误报很容易顺手把真报也放过去。

## 5. 回填入口（今天没改，但这是关键缺口）

- [ ] 卦例库 → 点开某条 → 能否顺利回填「事之成败 / 应期是否按时」
- [ ] 填完命中率统计是否从 `0 / 14` 变化

**目前 D1 里 14 条卦例、回填 0 条。** 所有指标测的都是「模型是否听话」，
没有一条能回答「断得准不准」。**先回填 3 条**，比再修 100 条审计规则有用。

## 出问题怎么回滚

```bash
# 看当前线上是哪个版本
npx wrangler pages deployment list --project-name=liuyao | head

# 回滚到上一版（保留的 deployment）
npx wrangler pages deployment rollback <deployment-id> --project-name=liuyao

# 或从 git 重新部署旧提交
git checkout 437205a~1 && npx wrangler pages deploy public --project-name=liuyao --branch=main
```

配置类回退不需要改代码：

| 想恢复 | 做法 |
|---|---|
| 首轮也吃缓存 | 设 `LLM_CACHE_FIRST=1` |
| 关掉 gemini 参数对照开关 | 不设 `LLM_DEBUG_VARIANTS` 即可（默认就是关） |
